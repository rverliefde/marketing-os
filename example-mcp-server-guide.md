# Example: Explainer / How-To Guide
**Source:** blog.clicksend.com/mcp-server-guide/ — "What is MCP? Your plain English guide to Model Context Protocol"
**Author:** Anna Christensen | **Category:** SMS guides | **Length:** ~4 min read

## Content type
Educational explainer that introduces an unfamiliar technical concept, then pivots into a product tie-in and setup guide.

## Structure pattern
1. **Hook** — relatable pain point stated in plain language (AI is smart but can't take real-world action)
2. **Plain-English definition** — jargon term defined simply, then restated as an analogy ("MCP is the bridge between...")
3. **How it works** — mechanism explained with a simple metaphor (translator between two worlds)
4. **Use case list** — short bolded category + one-line explanation, repeated for ~6 items
5. **Fun/social proof section** — lighter, entertaining real-world examples (sourced from Reddit) to build credibility and shareability before pivoting back to business use
6. **Product tie-in** — natural transition from general concept to "here's how ClickSend does this specifically"
7. **"Who is this for?"** — bulleted audience list, naming specific roles/teams
8. **Step-by-step setup** — numbered, concrete, includes a code snippet
9. **Forward-looking close** — brief "what's next" framing, ends on an aspirational one-liner
10. **CTA block** — bolded restatement of value prop + low-friction action ("Free to set up. No code required.")

## Tone
Conversational, plain-English, second person ("you"). Light humor in the examples section. Avoids jargon or defines it immediately when used.

## Formatting devices
- Short paragraphs (2-3 sentences max)
- Bolded sub-labels within list items
- Embedded inline CTAs mid-article, not just at the end
- Code block for technical setup step

## Useful for tool tailoring
This is the pattern to reuse for: new feature explainers, "what is X" guides, technical concepts aimed at a non-technical business audience.
